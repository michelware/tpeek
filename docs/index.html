How it works

Listen. Point. Read.

Three steps, nothing hidden. TPeek is a plain TCP proxy: the client talks to it, it talks to the server, and you see both sides.

1. Listen

tpeek -l 127.0.0.1:8000 -t 127.0.0.1:3306 listens on port 8000 and forwards everything to your MySQL on 3306.

2. Point

Point your application at 127.0.0.1:8000 instead of the real server. Nothing else changes for the app or the server.

3. Read

Every read is printed as a block: connection number, direction, timing, size and stream offset. In plain text, or in hex with -hex.

Why TPeek

Made for reading a conversation.

A packet capture shows how the network cut the data. TPeek shows what your application actually receives, as one story, on one timeline.

No privileges

No sudo, no capture driver, no certificate to install. Drop one binary on a server, a laptop or in a container and run it.

Any protocol

HTTP, MySQL, PostgreSQL, Redis, SMTP, MQTT, a homemade binary protocol. No dissector needed: if it goes over TCP, you see it.

Reads, not packets

One block per Read() on the socket, with its offset in the stream: exactly what your parsing code has to handle.

Plain words

Numbered connections, clean close (EOF) or abrupt reset, who stopped first, and a summary per connection. Easy to read, easy to grep.

Compare

Like Wireshark or socat -v, without the setup.

Those tools are great and answer other questions. TPeek does one job: show the bytes of a TCP conversation, from any machine, in seconds.

Scope

What TPeek will never do

A single Go file you can read in one sitting stays a tool you can trust. TPeek will not grow into a packet analyzer.

  • change a single byte
  • cut idle connections
  • delay data for the display
  • require root or a driver
  • send control codes to your terminal
  • install a certificate
